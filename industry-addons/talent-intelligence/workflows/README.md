# Workflows

Production-tier guidance and operational decision trees for talent-industry imagery work.

The parent BHIL playbook documents four cross-platform workflow recipes (single-model, NB→MJ, typography compositing, etc.). This directory adds talent-industry-specific operational guidance: how to choose between speed and archival quality, and how to operationalize the candidate-imagery decision at every imagery request.

## Files

| File | Purpose |
| :--- | :--- |
| [`three-production-tiers.md`](./three-production-tiers.md) | Three production tiers (fast iteration, mid-tier, archival quality) with timeline, tooling, AI-use policy, and team composition per tier. |
| [`candidate-imagery-decision-tree.md`](./candidate-imagery-decision-tree.md) | Operational version of the decision tree from [`../docs/03-candidate-imagery-problem.md`](../docs/03-candidate-imagery-problem.md), with documentation requirements at each node. |

## Tier Selection — Quick Guide

| Deliverable | Default Tier |
| :--- | :-: |
| LinkedIn recruiter posts, social tiles | 1 |
| Job posting headers, internal comms | 1 |
| Career site refresh, EVP launch | 2 |
| Conference materials, vendor pitch decks | 2 |
| Salary guides, regular workforce content | 2 |
| Executive search dossiers | 3 |
| Annual workforce reports (Korn Ferry, Mercer, Lightcast tier) | 3 |
| Annual DEI reports | 3 |
| Board search deliverables | 3 |

## Decision-Tree Application

Every imagery request — regardless of tier — passes through the candidate-imagery decision tree before generation begins. The tree is fast in practice (most decisions take seconds) but its documentation requirement ensures defensible-by-default posture.
